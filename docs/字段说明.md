### 文本版本记录示例

当前项目按“每首诗只保留一个认可度较高的主版本”执行，不在主数据表并列多个正文版本。一个可追溯的简体展示记录可以这样理解：

```text
poem_id: poem_...
title: 静夜思
full_text: 床前明月光，\n疑是地上霜。\n举头望明月，\n低头思故乡。
source_id: src_...
source_locator: 《全唐诗》卷一百八十四；维基文库固定修订页
variant_notes: 主文本采用选定底本；来源页保留繁体；其他异文不进入主表和统计；展示层统一转为简体；原始文本和转换哈希见 reports/tang_poem_text_normalization_v1.csv
review_status: pending
```

这里的含义是：`full_text` 是当前用于统计和前端展示的采用文本，`source_id` 与 `source_locator` 指向底本，`variant_notes` 解释异文和简繁转换，`review_status` 记录这条记录当前是否完成项目规定的审核流程。`pending` 不表示正文为空或不能用于原型，而表示正式审核签名尚未写入。

### 一个具体的异文处理例子

以《静夜思》为例，项目展示层可以采用通行文本“床前明月光，疑是地上霜。举头望明月，低头思故乡。”；如果底本或校注资料还记录“牀前看月光”“举头望山月”等异文，不应直接覆盖展示文本，也不应把两个版本混合统计。正确做法是：

1. `full_text` 只放已经选定的主版本，并统一转为简体用于展示和统计；
2. `source_id` 与 `source_locator` 指向主版本的具体出处；
3. `variant_notes` 记录异文、选择理由和简繁转换；
4. 原始文本、转换前后哈希和审计时间写入 `reports/*text_audit*.csv`；
5. 若以后要同时展示多个版本，再新增独立的 `text_versions.csv`，而不是把异文塞进 `full_text`。

这样既能保持简体界面，也能让每个统计结果回到实际采用的文本版本。

当前不新增 `text_versions.csv`；如果未来确实要做版本对照，再单独建立版本表，不改变当前唯一主版本的统计口径。

### public_sources（公开来源目录）

该表由 `scripts/build_public_sources_v1.py` 从诗作实际引用的 `source_id` 去重生成。多个诗作可以共用同一个来源，因此行数通常少于诗作数。

|字段|含义|
|---|---|
|source_id|对应 `sources.csv` 的来源编号|
|title|来源名称|
|source_type|来源类型|
|url|来源链接|
|license|公开许可名称|
|license_url|许可文本链接|
|attribution|对外署名|
|description|展示用途说明|

### public_poems（公开诗文表）

该表由 `scripts/build_public_poems_v1.py` 从 `poems.csv` 和 `poets.csv` 生成，供网页正文展示或对外提交使用。它只保留诗作标识、诗名、作者和选定正文；来源、许可和快照定位分别从 `public_sources.csv`、`public_poem_sources.csv` 查询，不把内部审核字段混入正文数据。

|字段|含义|
|---|---|
|poem_id|诗作稳定标识符，用于与公开来源映射和前端联动|
|title|诗名|
|author|作者展示名|
|full_text|选定的简体展示正文，保留必要标点和换行|

### public_poem_sources（诗—来源映射）

该表按 `poem_id` 生成一行，专门回答“这首诗的来源是什么”。当前160首诗应有160行；同一个来源可以在多行重复出现。

|字段|含义|
|---|---|
|poem_id|诗作编号|
|title|诗名|
|author|作者名|
|source_id|对应 `sources.csv` 的来源编号|
|source_title|来源名称|
|source_url|来源链接|
|source_locator|Chinese Poetry 快照文件、记录序号和记录 ID|
|license|公开许可名称|
|license_url|许可文本链接|
|attribution|对外署名|
